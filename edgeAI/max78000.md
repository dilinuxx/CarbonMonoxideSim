# MAX78000FTHR Flashing with MSDK and OpenOCD

A quick guide for building and flashing firmware to the **MAX78000FTHR** development board using the **Analog Devices MSDK** and the onboard **CMSIS-DAP** debugger.

This guide covers both **Windows** and **Ubuntu/Linux** development.

## Requirements

### Hardware

- **MAX78000FTHR** development board
- USB cable

### Software

- Analog Devices **MSDK**
- **OpenOCD** included with the MSDK
- ARM GNU toolchain included with the MSDK

---

# Windows

## Build the Example Project

Open **PowerShell** and navigate to the example project:

```powershell
cd C:\MaximSDK\Examples\MAX78000\Hello_World


Build the project:

make


After a successful build, the generated ELF file will be located at:

C:\MaximSDK\Examples\MAX78000\Hello_World\build\max78000.elf

Flash the Firmware

Connect the MAX78000FTHR to the PC using the USB cable.

Run the following command from PowerShell:

& "C:\MaximSDK\Tools\OpenOCD\openocd.exe" `
-s "C:\MaximSDK\Tools\OpenOCD\scripts" `
-f interface/cmsis-dap.cfg `
-f target/max78000.cfg `
-c "program C:/MaximSDK/Examples/MAX78000/Hello_World/build/max78000.elf verify reset exit"


The command uses:

interface/cmsis-dap.cfg — onboard CMSIS-DAP debugger
target/max78000.cfg — MAX78000 target configuration
program — programs the ELF into flash
verify — verifies the programmed contents
reset — resets the MAX78000
exit — closes OpenOCD after programming
Successful Flash Output

A successful programming operation ends with output similar to:

** Programming Finished **
** Verify Started **
** Verified OK **
** Resetting Target **


The MAX78000 will automatically reset and begin executing the newly flashed firmware.

Ubuntu / Linux
Install the MSDK

Download the Linux MSDK installer, for example:

MaximMicrosSDK_linux.run


Make the installer executable:

chmod +x MaximMicrosSDK_linux.run


Run the installer:

./MaximMicrosSDK_linux.run


The SDK can be installed under:

~/MaximSDK


After installation, the directory should contain:

~/MaximSDK/
├── Examples/
├── Libraries/
├── Tools/
├── setenv.sh
└── ...

Configure the MSDK Environment

The Linux MSDK uses the MAXIM_PATH environment variable.

Set it explicitly before sourcing setenv.sh:

export MAXIM_PATH=$HOME/MaximSDK
source ~/MaximSDK/setenv.sh


Verify the environment:

echo "MAXIM_PATH=$MAXIM_PATH"
echo "FIRMWARE_PATH=$FIRMWARE_PATH"
echo "TOOLCHAIN_PATH=$TOOLCHAIN_PATH"


Expected output:

MAXIM_PATH=/home/<username>/MaximSDK
FIRMWARE_PATH=/home/<username>/MaximSDK/Libraries
TOOLCHAIN_PATH=/home/<username>/MaximSDK/Tools

Important: MAXIM_PATH

If MAXIM_PATH was previously set incorrectly, for example:

MAXIM_PATH=/usr/bin


setenv.sh may use the incorrect value.

Fix it with:

unset MAXIM_PATH
export MAXIM_PATH=$HOME/MaximSDK
source ~/MaximSDK/setenv.sh


Then verify:

echo "$MAXIM_PATH"


It should show:

/home/<username>/MaximSDK


Note: The installed Linux MSDK uses MAXIM_PATH. Do not use MSDK as the primary environment variable.

Build the Example Project

Navigate to the MAX78000 Hello World example:

cd ~/MaximSDK/Examples/MAX78000/Hello_World


Build the project:

make clean
make


A successful build produces:

~/MaximSDK/Examples/MAX78000/Hello_World/build/max78000.elf


Verify the output:

ls -lh build/max78000.elf


The build also reports memory usage, for example:

FLASH:       39424 B       512 KB      7.52%
SRAM:         3824 B       128 KB      2.92%

Verify the ARM Toolchain

The ARM compiler is supplied by the MSDK:

which arm-none-eabi-gcc


Expected:

/home/<username>/MaximSDK/Tools/GNUTools/10.3/bin/arm-none-eabi-gcc


Check the compiler version:

arm-none-eabi-gcc --version

OpenOCD
Verify OpenOCD

The MSDK installs OpenOCD under:

~/MaximSDK/Tools/OpenOCD


The executable is located at:

~/MaximSDK/Tools/OpenOCD/bin/openocd


There is also a symlink:

~/MaximSDK/Tools/OpenOCD/openocd


Check the OpenOCD version:

~/MaximSDK/Tools/OpenOCD/bin/openocd --version


A working installation reports something similar to:

Open On-Chip Debugger (Analog Devices 0.12.0-1.0.0-7)
OpenOCD 0.12.0

Verify the OpenOCD Configuration Files

The required configuration files should exist:

~/MaximSDK/Tools/OpenOCD/scripts/interface/cmsis-dap.cfg
~/MaximSDK/Tools/OpenOCD/scripts/target/max78000.cfg


Check them with:

find ~/MaximSDK/Tools/OpenOCD \
    -name "cmsis-dap.cfg" \
    -o -name "max78000.cfg"


Expected output includes:

/home/<username>/MaximSDK/Tools/OpenOCD/scripts/interface/cmsis-dap.cfg
/home/<username>/MaximSDK/Tools/OpenOCD/scripts/target/max78000.cfg

Test the CMSIS-DAP Connection

Connect the MAX78000FTHR to Ubuntu using USB.

You can check that the USB device is detected with:

lsusb


Then start OpenOCD:

~/MaximSDK/Tools/OpenOCD/bin/openocd \
    -s ~/MaximSDK/Tools/OpenOCD/scripts \
    -f interface/cmsis-dap.cfg \
    -f target/max78000.cfg


A successful connection should show output similar to:

Info : CMSIS-DAP: SWD supported
Info : CMSIS-DAP: Interface Initialised (SWD)
Info : CMSIS-DAP: Interface ready
Info : clock speed 2000 kHz
Info : SWD DPIDR 0x2ba01477
Info : [max32xxx.cpu] Cortex-M4 r0p1 processor detected
Info : [max32xxx.cpu] target has 6 breakpoints, 4 watchpoints


The important messages are:

CMSIS-DAP: Interface ready
SWD DPIDR 0x2ba01477
Cortex-M4 r0p1 processor detected


This confirms that Ubuntu can communicate with the MAX78000 through the onboard CMSIS-DAP debugger.

Stop OpenOCD with:

Ctrl+C

Flash the Firmware on Ubuntu

Use the absolute path to the ELF file when passing it to OpenOCD.

Important

Do not use:

-c "program ~/MaximSDK/Examples/MAX78000/Hello_World/build/max78000.elf ..."


The ~ is not expanded inside the command string passed to OpenOCD.

Instead, use an absolute path:

-c "program /home/<username>/MaximSDK/Examples/MAX78000/Hello_World/build/max78000.elf verify reset exit"


For example, for a user named dilinox:

~/MaximSDK/Tools/OpenOCD/bin/openocd \
    -s ~/MaximSDK/Tools/OpenOCD/scripts \
    -f interface/cmsis-dap.cfg \
    -f target/max78000.cfg \
    -c "program /home/dilinox/MaximSDK/Examples/MAX78000/Hello_World/build/max78000.elf verify reset exit"


A successful programming operation produces:

** Programming Started **
** Programming Finished **
** Verify Started **
** Verified OK **
** Resetting Target **
shutdown command invoked


** Verified OK ** confirms that the programmed flash contents were successfully verified.

The MAX78000 will then reset and begin executing the newly flashed firmware.

Serial Output on Ubuntu

The MAX78000FTHR may expose a USB serial device to Linux.

Check for serial devices:

ls /dev/ttyACM* /dev/ttyUSB* 2>/dev/null


For example:

/dev/ttyACM0


Check the device permissions:

ls -l /dev/ttyACM0


For example:

crw-rw----+ 1 root plugdev 166, 0 /dev/ttyACM0


If the device is accessible, open a serial terminal at 115200 baud:

screen /dev/ttyACM0 115200


Reset the MAX78000FTHR using the board's reset button and observe the terminal for the example's output.

If screen is not installed:

sudo apt update
sudo apt install screen


Then:

screen /dev/ttyACM0 115200


To exit screen:

Ctrl+A
K


Then confirm the exit.

Troubleshooting
MAXIM_PATH points to /usr/bin

If make reports:

Warning: MAXIM_PATH is not set!


or attempts to use:

/usr/bin/Libraries


reset the environment:

unset MAXIM_PATH
export MAXIM_PATH=$HOME/MaximSDK
source ~/MaximSDK/setenv.sh


Verify:

echo "$MAXIM_PATH"


It should report:

/home/<username>/MaximSDK

openocd: No such file or directory

Check that the executable exists:

ls -lh ~/MaximSDK/Tools/OpenOCD/bin/openocd


The executable should be several megabytes in size.

Check it with:

file ~/MaximSDK/Tools/OpenOCD/bin/openocd


Then test:

~/MaximSDK/Tools/OpenOCD/bin/openocd --version


A valid installation should return the OpenOCD version.

If bin/openocd is reported as an empty file (0 bytes), the OpenOCD installation is incomplete or corrupted. Reinstall or repair the OpenOCD component of the MSDK.

OpenOCD runs but cannot find the ELF

Do not use:

-c "program ~/MaximSDK/..."


Use the absolute path instead:

-c "program /home/<username>/MaximSDK/Examples/MAX78000/Hello_World/build/max78000.elf verify reset exit"

CMSIS-DAP is not detected

Check that the board is connected:

lsusb


Then retry:

~/MaximSDK/Tools/OpenOCD/bin/openocd \
    -s ~/MaximSDK/Tools/OpenOCD/scripts \
    -f interface/cmsis-dap.cfg \
    -f target/max78000.cfg


Make sure:

The MAX78000FTHR is connected via USB.
The board is powered.
The CMSIS-DAP USB interface is connected.
No other debugger application is already using the CMSIS-DAP interface.
Complete Ubuntu Workflow

Once the MSDK is installed, the complete build and flash workflow is:

unset MAXIM_PATH
export MAXIM_PATH=$HOME/MaximSDK
source ~/MaximSDK/setenv.sh

cd ~/MaximSDK/Examples/MAX78000/Hello_World

make clean
make

~/MaximSDK/Tools/OpenOCD/bin/openocd \
    -s ~/MaximSDK/Tools/OpenOCD/scripts \
    -f interface/cmsis-dap.cfg \
    -f target/max78000.cfg \
    -c "program /home/$USER/MaximSDK/Examples/MAX78000/Hello_World/build/max78000.elf verify reset exit"


A successful result ends with:

** Programming Finished **
** Verify Started **
** Verified OK **
** Resetting Target **
shutdown command invoked


At this point the MAX78000FTHR is programmed and running the newly built firmware.

Notes
The onboard CMSIS-DAP debugger is used for SWD programming.
The MSDK supplies the ARM GNU toolchain and OpenOCD.
The Linux MSDK environment uses MAXIM_PATH.
Ensure the MAX78000FTHR is connected and powered during programming.
On Ubuntu, /dev/ttyACM0 may be used for serial output when exposed by the board/debug interface.
Use an absolute ELF path inside OpenOCD's program command.
** Verified OK ** confirms successful flash verification.
